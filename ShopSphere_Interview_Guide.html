1. PROJECT OVERVIEW — "Tell me about your project"

ShopSphere is a full-stack e-commerce management system that I built using Java Spring Boot for the backend, React.js for the frontend, and MySQL as the database. It simulates a real-world online shopping platform with features like JWT-based authentication, product catalog with search and filtering, shopping cart, order management, wishlist, payment integration, and an admin dashboard with sales analytics.

The backend follows a layered architecture (Controller → Service → Repository → Entity) and uses Spring Security with JWT tokens for stateless authentication. The frontend is a Single Page Application (SPA) built with React, using React Router for navigation and Axios for API communication.

5. CORE FEATURES

5.1 JWT Authentication Flow

  1. Register: User submits credentials → password hashed with BCrypt → saved to DB
  2. Login: Credentials validated → JWT token generated (HMAC-SHA, 24hr expiry) → returned to frontend
  3. API Calls: Axios interceptor adds Authorization: Bearer <token> to every request
  4. Server: JwtAuthenticationFilter validates token → sets SecurityContext → request proceeds

5.2 Role-Based Access Control

  • ROLE_USER: Browse, cart, orders, wishlist
  • ROLE_ADMIN: Everything + manage products, all orders, analytics, user management
  • Enforced at URL level (SecurityConfig) and method level (@PreAuthorize)

5.3 Product Management

  • Pagination: PageRequest.of(page, size, sort) returns Page<Product>
  • Search: JPQL query across name, description, brand
  • Filtering: By category ID
  • Soft Delete: Products deactivated, not deleted (preserves order history)

5.4 Order Processing Flow

Cart Items → Validate Stock → Create Order → Create OrderItems
→ Deduct Stock → Create Payment → Clear Cart → Return Order
  • Tax: 8% on subtotal | Shipping: Free over $100, else $9.99
  • Status: PENDING → CONFIRMED → PROCESSING → SHIPPED → DELIVERED
  • Cancel allowed only in PENDING/CONFIRMED (restores stock)
  • All wrapped in @Transactional for atomicity

7. INTERVIEW QUESTIONS & ANSWERS

Q1: "Tell me about your project."
"ShopSphere is a full-stack e-commerce platform I built using Spring Boot and React. It features JWT authentication with role-based access control, a product catalog with search and pagination, shopping cart, order management with status tracking, wishlist, and an admin dashboard with sales analytics. The backend follows a layered architecture with Spring Data JPA and MySQL. I also containerized it with Docker."
Q2: "Why did you choose this tech stack?"
"Spring Boot is the industry standard for Java enterprise apps — it provides auto-configuration and excellent security integration. React was chosen for its component-based architecture and virtual DOM performance. MySQL was selected because e-commerce data is highly relational — orders reference users and products, benefiting from ACID compliance. JWT enables stateless, scalable API security."
Q3: "What was the most challenging part?"
"The order processing flow — it involves validating stock for all cart items, creating the order and items, deducting inventory, creating payment records, and clearing the cart. I used @Transactional to ensure atomicity — if any step fails, the entire operation rolls back."
Q4: "How do you handle errors?"
"I implemented a global exception handler using @RestControllerAdvice. It catches ResourceNotFoundException (404), BadRequestException (400), BadCredentialsException (401), and validation errors (field-level messages). This ensures consistent error responses across all endpoints."
Q5: "How does JWT work in your project?"
"On login, the server generates a JWT signed with HMAC-SHA containing the username, with 24-hour expiry. The frontend stores it in localStorage. An Axios interceptor adds it to every request as a Bearer token. On the server, a OncePerRequestFilter validates the token's signature and expiry, loads the user, and sets the SecurityContext."
Q6: "Authentication vs Authorization?"
"Authentication verifies WHO you are (login → JWT). Authorization determines WHAT you can do (ROLE_USER can place orders, ROLE_ADMIN can also manage products). Authentication is handled by JWT, authorization by Spring Security's role-based access control."
Q7: "Explain your database relationships."
"Users ↔ Roles is ManyToMany. Products → Categories is ManyToOne. CartItems links Users and Products. Orders have OneToMany with OrderItems. OrderItems reference Products. Payments have OneToOne with Orders. Wishlists connect Users and Products with unique constraint."
Q8: "How do you handle pagination?"
"Using Spring Data JPA's Pageable. The controller accepts page, size, sortBy parameters. I create PageRequest.of(page, size, Sort) and pass it to the repository. The response includes content, totalPages, totalElements — the frontend renders pagination controls from this metadata."
Q9: "What is @Transactional?"
"@Transactional ensures a method runs in a database transaction. If any exception occurs, all changes roll back. Critical for order processing — if stock deduction fails, the partially created order is rolled back."
Q10: "Difference between @Controller and @RestController?"
"@Controller returns view names (for server-rendered pages). @RestController = @Controller + @ResponseBody — returns JSON directly. Since I'm building a REST API for a React frontend, I use @RestController."
Q11: "How did you implement protected routes in React?"
"I created a ProtectedRoute component that checks AuthContext. If not authenticated, it redirects to /login using Navigate. For admin routes, it checks ROLE_ADMIN. This wraps protected pages in the route configuration."
Q12: "What design patterns did you use?"
"Repository Pattern (JPA repos), DTO Pattern (request/response objects), Singleton Pattern (Spring beans), Filter Chain (JWT filter), Builder Pattern (JWT construction)."
Q13: "How would you scale this application?"
"JWT is stateless, so multiple backend instances can run behind a load balancer. Database can use read replicas. Redis caching for product listings. Docker supports horizontal scaling. Frontend SPA can be served from a CDN."
